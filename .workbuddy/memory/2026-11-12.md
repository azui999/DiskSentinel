## 修复：双击 bat 闪退

根因：系统 PATH 里没有 `python` 命令（只有 py 启动器，且 py -3/-V:Astral 都解析不到可运行的解释器；AppData 的 Python313 目录只剩 Lib/Scripts 没有 python.exe）。用户双击 run.bat 时 python 不可用直接闪退。

解决方案：
- 用 uv 管理的解释器 `C:\Users\llj\AppData\Roaming\uv\python\cpython-3.12.14-windows-x86_64-none\python.exe` 建了项目 `.venv`，PySide6 6.12 + pyqtgraph 0.14 已装入。
- run.bat 重写：优先 `.venv\Scripts\pythonw.exe`（无控制台黑框）；venv 缺失时自动 `py -3 -m venv` + pip install 引导；CRLF 行尾。
- run_as_admin.bat 同步改为提权启动 pythonw。
- main.py 加了 sys.excepthook：异常写 `data/logs/error.log` 并弹窗，避免 bat/管理员启动方式下"闪退无报错"。
- 验证：真实平台（非 offscreen）启动 OK；经 cmd 启动 run.bat 后 python 进程正常拉起 main.py。

经验：bat 必须写 CRLF；不能用 cmd 从 bash/PowerShell 工具调用（被安全策略拦截），bat 链路验证用 Start-Process + Win32_Process 查 CommandLine。

## 界面迭代：重复条目修复 + tooltip + CDI 式展示

用户反馈三个问题：①点立即检测后左侧多出一个"未连接"的 1TB 重复条目；②看不懂指标含义/类型；③想借鉴 CrystalDiskInfo 的展示。

根因与修复：
- **重复条目**：管理员模式下 smartctl IDENTIFY 报容量 1000204886016，WMI 报 1000202273280，同一块盘差 2GB，旧 `_is_conflict` 按容量判冲突 → 分叉出 `__hash` 目录。修复：冲突只看型号；`find_key` 只按序列号匹配；Store 启动时自动迁移合并历史分叉（迁移+CSV 合并已实现并验证）。
- **tooltip**：normalize 增加 METRIC_INFO（每个指标"是什么+怎么判断"）、GROUP_INFO（关键/接口/磨损/运行四类含义）、NVME_INFO、ata_attr_info；指标明细的名称与类型列、四个状态卡全部挂上 tooltip。
- **借鉴 CDI**：头部卡新增 固件版本/接口(SATA)/盘符(Get-Partition 映射)/主机总计写入(241×512 或 NVMe data_units_written×512000)；总体状态显示剩余寿命百分比（NVMe percentage_used）；新增"属性表"页签（ATA: ID/名称/当前值/最差值/临界值/原始值/类型，NVMe: 属性/值/说明）。

重要教训：**wear_leveling 存的是 RAW 值（三星 870 上是 7），不是归一化值（99）**。用"100-raw"反推寿命是错的（算出 7%），必须用 ata_smart_attributes.table[].value。endurance_used 在管理员/非管理员下读数漂移（0/1），以 177 归一化值兜底后与 CDI 的 99% 一致。修复后老 CSV 行显示仍旧（需新快照）。

盘符映射：/dev/pdN ↔ Get-Partition DiskNumber，非管理员可用。

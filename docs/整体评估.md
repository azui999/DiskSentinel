# DiskSentinel 整体评估（2026-11-12）

> 结论先行：三大功能（硬盘健康 / 冷备对 / 单盘自检）核心链路全部走通、数据链路可靠，**可以日常使用**。
> 剩余工作以「体验补全」为主，没有影响正确性的重大缺口。

## 一、功能现状

| 模块 | 状态 | 说明 |
|------|------|------|
| 硬盘健康 | ✅ 成熟 | 扫描→检测→概览/属性表/趋势/健康报告，全手动带确认，非管理员降级可用 |
| 冷备对·结构比对 | ✅ 成熟 | 双树对位视图、同步滚动、按需展开；历史页可重放 |
| 冷备对·内容校验 | ✅ 成熟 | SHA-256 全量比对、暂停续跑、快速模式显式勾选（默认关闭，防漏检） |
| 单盘自检 | ✅ 成熟 | 固定基线不滚动、六类差异、当前 vs 基线树视图 |
| 校验历史 | ✅ 成熟 | 三类运行记录统一时间线，明细现场重放不占空间 |
| 数据存储 | ✅ | SMART 用文件（人眼可读），文件功能用 SQLite（index.db），README 有备份说明 |

## 三、建议清单

> 2026-11-12 更新：P1（1-4）与 P2（5-7）已全部实现，见文末「五、本轮新增」。

### P1（建议下一轮做，都是小改动）✅ 已完成
1. **报告导出为文件**：健康报告现在只能复制到剪贴板，加一个「导出 TXT/HTML」按钮更完整。
2. **全局忙碌指示**：内容校验跑到 6~8 小时，用户切到别的页签就看不到进度了。
   建议在顶栏或状态栏放一个小的「校验进行中…」指示，点击跳回对应页签。
3. **一键备份数据**：data 目录（disks.json + snapshots + index.db）打包成 zip 到指定位置，
   换电脑/重装时一键恢复。README 已有手动步骤，界面化一步即可。
4. **删除确认后可撤销**：删除冷备对/自检目标是软删除还是真删，值得明确——
   现在是真删（含历史记录）。建议删除前提示可先导出，或做 30 天内可恢复。

### P2（锦上添花，可选）✅ 已完成
5. 趋势页多指标叠加（温度 + 寿命消耗同图双轴）。
6. 盘对/自检结果对比视图（本次 vs 上次的差异变化：新增了哪些坏文件）。
7. 硬盘健康页支持「导出 CSV」原始属性，方便长期归档分析。

### 不建议做（与产品原则冲突）
- ❌ 定时自动扫描 / 后台常驻托盘：本工具的核心原则是**全部手动、操作可见**，
  自动化会让用户失去对"什么时候读了哪块盘"的掌控，还可能与备份软件抢盘。
- ❌ 多语言：家用工具，中文单语言足够。

## 四、UI 打磨（本轮已完成）

- 统一设计系统：间距 8px 网格、圆角 7/10px、字号层级（页面标题/正文 13px/辅助 12px）。
- 统计卡统一为「标题在上、22px 数值在下、左对齐」，健康页与文件功能页一致。
- 冷备对/自检信息卡：路径加 A / B / 路径 徽章，信息层级更清晰。
- 状态栏精简：smartctl 完整路径移入 tooltip，只留版本与管理员提示。
- 树、表格行距与表头留白加大，滚动条收窄。

## 五、本轮新增（2026-11-12 晚，P1 + P2 全部落地）

| 项 | 实现 | 入口 |
|---|---|---|
| P1-1 报告导出 | TXT（纯文本）与 HTML（带样式、可直接打印），默认存桌面，文件名含型号与日期 | 健康报告页 →【导出…】 |
| P1-2 全局忙碌指示 | 顶栏胶囊按钮实时显示「内容校验 42%」等，切任何页签都可见，点击跳回运行中的页面 | 顶栏（运行时出现） |
| P1-3 一键备份 | data 目录打包 zip；SQLite 走 backup API 生成一致快照（WAL 下也安全），失败不残留半截文件 | 状态栏 →【备份数据】 |
| P1-4 删除可撤销 | 冷备对 / 自检目标改为软删除进回收站，历史记录保留；彻底删除需二次确认 | 状态栏 →【回收站 (N)】 |
| P2-5 趋势双轴 | 「对比」下拉叠加第二指标：左轴蓝实线、右轴橙虚线、图例标注，任意两指标可组合 | 趋势页 → 对比下拉 |
| P2-6 与上次对比 | 最近两次运行的问题集合对比：本次新出现（含问题升级如"大小不同→内容不同"）/ 上次有本次已没有 | 盘对校验 / 单盘自检 →【与上次对比】 |
| P2-7 CSV 导出 | 属性表整表导出 + 全部历史指标导出（utf-8-sig，Excel 直接打开） | 属性表 / 趋势页 →【导出 CSV】 |

实现要点：
- 回收站 = `pairs` / `watch_targets` 加 `deleted_at` 列，所有列表查询与历史页自动过滤已删除对象；
  自检目标 `path` 有 UNIQUE 约束，回收站里同路径的行在重新添加时自动复用（历史一并恢复）。
- `watch_targets` 建表在新库上缺少软删除列的边界情况已修（ensure_schema 统一补列）。
- 备份 zip 内的 `index.db` 是 SQLite 快照，跳过 `-wal/-shm`，保证恢复时可直接用。
